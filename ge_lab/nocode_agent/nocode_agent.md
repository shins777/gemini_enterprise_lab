# 🤖 Gemini Enterprise No-Code, Multi-Agent & Workflow Agent 핸즈온 랩 가이드

본 문서는 **Gemini Enterprise App**의 내장 **Agent Designer(로우코드/노코드 에이전트 스튜디오)**를 활용하여, 복잡한 프로그래밍이나 외부 개발 프레임워크 없이도 누구나 최고 수준의 **단일 No-Code 에이전트**, **비즈니스 워크플로우 에이전트(Workflow Agent)**, 그리고 **계층형 멀티 에이전트(Multi-Agent System)**를 직접 설계·제작·스케줄링하고 조직 내에 배포할 수 있도록 구성된 실무 핸즈온 랩 가이드입니다.

## 1. No-Code Agent 환경 개요 및 핵심 개념

### 1.1 No-Code Agent란 무엇인가?
**No-Code Agent**란 복잡한 소프트웨어 코딩, 백엔드 서버 구축, 외부 API 연동 없이 웹 브라우저 기반의 **직관적인 자연어 프롬프트와 그래픽 빌더 인터페이스(GUI)**만으로 목적에 특화된 AI 업무 에이전트를 직접 제작하고 실행할 수 있는 Gemini Enterprise의 핵심 기능입니다.

비즈니스 기획자, 마케터, 인사/채용 담당자, 영업 대표 등 현업 실무자 누구나 자신의 전문 업무 지식(Domain Knowledge)을 에이전트에 주입하여 즉시 활용 가능한 사내 전용 AI 팀원을 손쉽게 구축할 수 있습니다.

### 1.2 일반 챗봇(General Chat)과의 차이점

| 비교 항목 | 일반 Gemini 챗 (General Chat) | Gemini No-Code Agent |
| :--- | :--- | :--- |
| **역할 및 페르소나** | 매 세션마다 프롬프트로 역할을 재부여해야 함 | 에이전트 생성 시 정의된 전문 역할과 비즈니스 룰이 **영구 고정**됨 |
| **지식 베이스 (Knowledge)** | 사용자가 대화 세션마다 관련 문서를 수동 업로드 | 사내 정책, 평가 기준표, 매뉴얼이 **에이전트에 사전 바인딩**됨 |
| **도구 활용 (Tools)** | 사용자가 수동으로 검색/커넥터 툴을 지정 | Google Search, Enterprise Connectors를 **에이전트가 자율 연쇄 호출** |
| **출력 형식 (Format)** | 일반적인 서술형 텍스트 응답 | 사전에 정의된 **표, 평가표, 리포트 템플릿 서식을 100% 준수** |
| **실행 방식** | 사용자의 즉각적인 1회성 입력에만 반응 | **주기적 스케줄(Cron) 자동 실행** 및 백그라운드 비동기 처리 지원 |
| **협업 및 거버넌스** | 개인 세션에 완전히 격리 | 조직/부서 단위로 **공유 및 중앙 권한 통제** 가능 |

### 1.3 3대 에이전트 구축 패러다임

```mermaid

    subgraph "1. No-Code Single Agent"

    end

    subgraph "2. Workflow Agent"
        J[Schedule: 매일 09:00] --> K[1단계: AI 시장 뉴스 수집 & 위협 수준 분석]

        L -->|High: 고위협| M[3단계: 홍보 지침 입력 & 사람 필수 승인]
        L -->|Else: 일반| N[3단계: 질문1 입력 & 즉시 자동 완성]
        M --> O[📧 최종 브리핑 이메일 자동 발송]
```

1. **No-Code 단일 에이전트 (Single Agent)**: 자연어 대화 또는 노드 빌더를 통해 생성되며, 특정 반복 업무(예: 소셜 미디어 게시물 작성, 역사 인사이트 도출)를 완결하는 기본 에이전트.
2. **워크플로우 에이전트 (Workflow Agent)**: 프롬프트 지시를 통해 스케줄 트리거, 데이터 수집, 조건 분기(Branching), 인간 입력 및 필수 승인(Review), 이메일 발송 액션으로 이어지는 다단계 자동화 파이프라인을 구축하는 에이전트.
3. **계층형 멀티 에이전트 (Hierarchical Multi-Agent System)**: 루트 오케스트레이터(Root Agent) 1개가 하위 전문 에이전트(Sub-Agents) 3개를 지정된 순서대로 호출하고, 중간 산출물을 다음 에이전트에게 맥락(Context)으로 인수인계(Hand-off)하여 최종 단일 종합 보고서를 작성하는 엔터프라이즈 시스템.

### 2.2 Agent Designer 인터페이스 레이아웃 및 조작법

- **Agent 메뉴 진입**: 좌측 메인 네비게이션 바에서 **Agents** 아이콘을 클릭합니다.
- **새 에이전트 생성 버튼**:
  - **자연어 프롬프트 모드**: 하단 텍스트 입력창에 에이전트의 역할, 파이프라인 단계, 조건 분기, 도구 연동을 서술하면 AI가 이름, 설명, 지침, Flow 뷰를 자동으로 완벽히 구성합니다.
  - **빌더로 진행 (Proceed with Builder)**: 노드 기반 비주얼 캔버스에서 이름, 설명, 모델, 지식 문서, 도구, 시스템 지침을 정밀하게 수동 세팅합니다.
- **에이전트 노드 속성 패널**:
  - **Name & Description**: 에이전트의 명칭 및 역할 요약
  - **Model 선택**: 작업의 성격에 따라 `Gemini 3.5 Flash` 또는 `Gemini 3.5 Pro` 지정
  - **Knowledge (지식)**: Google Drive 내 문서 또는 PDF/문서 파일을 바인딩하여 RAG 기반 사내 지식 고정
  - **Connectors / Tools**: `Google Search`, `Gmail (Email Action)`, `Approval Action` 등 도구 활성화
  - **원시 텍스트 모드 (Raw Text Mode)**: 복잡한 비즈니스 룰과 시스템 프롬프트를 마크다운 구조로 직접 작성
  - **시작 프롬프트 (Starting Prompts)**: 사용자가 대화 시작 시 클릭할 수 있는 추천 프롬프트 칩(Prompt Chips) 등록
- **Flow 뷰 (Workflow Flowchart)**: 트리거, 검색 노드, 조건 분기 노드, 인간 입력 필드, 승인 게이트, 이메일 발송 액션 간의 연결 관계를 시각적 흐름도로 조망하고 검증합니다.

> 💬 **워크플로우 에이전트 생성 프롬프트:**
> ```text
> 매일 오전 9시에 자동 실행되는 'AI 시장 뉴스 분석 및 경영진 브리핑 워크플로우 에이전트'를 만들어줘.
> 이 워크플로는 최신 AI 시장 뉴스를 분석해 경영진 브리핑을 작성하며, 총 3단계로 진행돼:
> 
> 1. 데이터 수집 및 분석:
> - Google 검색 도구를 활용해 지난 24시간 동안의 'AI 규제' 및 '기업 AI 도입' 뉴스를 실시간으로 수집해.
> - 수집된 정보를 바탕으로 시장 요약, 주요 핵심 주제, 그리고 기업에 미치는 위협 수준('High' 또는 'Low')을 자동 도출해.
> 
> 2. 조건 분기:
> - 분석된 위협 수준에 따라 작업을 'High(고위협)' 트랙과 'Else(일반)' 트랙 두 가지 경로로 자동 전환해.
> 
> 3. 트랙별 실행, 승인 및 이메일 발송:
> • High 트랙:
>   - 담당자에게 장문의 '홍보 대응 전략 지침' 입력을 요청해.
>   - 담당자가 입력한 지침과 시장 요약을 통합하여 완성도 높은 전문 브리핑 초안을 작성해.
>   - 리스크 관리를 위해 사람의 필수 승인(Review/Approval) 절차를 거치도록 해.
>   - 승인이 완료되면 최종 브리핑 결과를 로그인한 사용자의 구글드라이브에 즉시 저장해.
> • Else 트랙:
>   - 사용자에게 간단한 '질문 1' 텍스트 입력을 받아.
>   - 별도의 승인 절차 없이 시장 요약만으로 일반 브리핑 초안을 즉시 자동 완성해.
>   - 완성된 최종 일반 브리핑 결과를 로그인한 사용자의 구글드라이브에 즉시 저장해.
> 
> 전체적인 최종 처리 결과는 사용자가 구글 드라이브에서 확인할수 있도록 로그인한 계정의 구글 드라이브에 저장해줘. 
> 에이전트 구성 및 모든 안내 문구, 질문 폼, 브리핑 양식 작성시 언어는 완벽한 한국어로 작성해줘.
> ```

### Lab 5. 채용 전형 총괄 오케스트레이터 및 서브 에이전트 설계

채용 서류 검토 업무를 위해, 단일 에이전트의 토큰 및 추론 한계를 극복하는 **루트 오케스트레이터(Root Agent) 1개 + 전문 하위 에이전트(Sub-Agents) 3개**로 구성된 계층형 멀티 에이전트 아키텍처를 설계합니다.

```mermaid
graph TD
    A[사용자: 지원서 PDF 첨부] --> B[Root: GOOG전자 채용 총괄 에이전트]
    B -->|Step 1: 심층 서류 평가 의뢰| C[Sub 1: 서류 심층 평가자]
    C -->|점수 100점 & 인재상 & 리스크 반환| B
    B -->|Step 2: 고유명사 팩트체크 의뢰| D[Sub 2: 백그라운드 팩트체커]
    D -->|검증 결과 & Google Search URL 반환| B
    B -->|Step 3: 심층 면접 질문 의뢰<br>+ Step 1 평가 및 Step 2 팩트체크 맥락 전달| E[Sub 3: 면접 질문 기획자]
    E -->|기술적 압박 꼬리 질문 3가지 반환| B
    B --> F[단 하나의 최종 종합 검토 리포트 출력]
```

#### 1) 메인 루트 에이전트 구성: GOOG전자 채용 총괄 에이전트
1. **새 에이전트** 클릭 ➔ **"빌더로 진행"** 선택.
2. 루트 에이전트 노드 속성을 다음과 같이 설정합니다:
   - **Name:** `GOOG전자 채용 총괄 에이전트`
   - **Description:** `채용 프로세스 전체를 총괄하며, 하위 전문가 에이전트(Sub-Agents)들을 지정된 순서대로 호출·실행하고 그 결과를 취합하여 최종 종합 리포트를 작성합니다.`
   - **Model:** `Gemini 3.5 Flash`
   - **Knowledge (지식):** `resources/files/2026년 GOOG전자 서류전형 평가 가이드라인.pdf` 바인딩
   - **대화 시작문 (Starting Prompt):** `지원자의 이력서를 첨부하세요`

<img style="border: 1px solid #e0e0e0; border-radius: 6px; box-shadow: 0 2px 5px rgba(0,0,0,0.05);" src="resources/img/lab5-1.png" width="600">

3. 요청사항(Instruction) 창에서 **"원시 텍스트 모드 전환"**을 클릭하고 아래 내용을 입력합니다:

```text
## Role
당신은 GOOG전자의 채용 프로세스 전체를 오케스트레이션(통제 및 조율)하는 메인 에이전트입니다. 당신의 유일한 역할은 3명의 하위 전문가 에이전트를 정해진 순서대로 호출하고, 그들이 반환한 결과를 누락 없이 매끄럽게 취합하여 하나의 최종 종합 리포트를 작성하는 것입니다. 스스로 지원서를 직접 분석하거나 평가하지 말고, 반드시 하위 에이전트의 결과물만을 활용하십시오.

## Execution Protocol (Mandatory)
당신은 반드시 아래의 단계를 순차적으로, 엄격하게 실행해야 합니다.
1. Silent Execution: 사용자에게 현재 어떤 단계를 진행 중인지, 계획이 무엇인지 설명하는 중간 프로세스를 절대 노출하지 마십시오. 오직 최종 결과만 출력해야 합니다.
2. Step 1 (심층 평가): '서류 심층 평가자' 에이전트를 호출하여 지원서 심층 평가 점수와 의견을 요청하고 결과를 수집하십시오.
3. Step 2 (팩트 체크): '백그라운드 팩트체커' 에이전트를 호출하여 고유명사 검증 리포트를 요청하고 결과를 수집하십시오.
4. Step 3 (면접 질문 기획): '면접 질문 기획자' 에이전트를 호출하십시오. 이때 반드시 앞선 Step 1과 Step 2에서 수집한 '심층 평가 결과'와 '팩트체크 검증 리포트' 전체 내용을 '면접 질문 기획자'에게 컨텍스트(Context) 입력값으로 함께 전달해야 합니다.

## Output Expectations
모든 하위 에이전트의 작업이 완료되면, 전달받은 결과들을 종합하여 아래 구조를 모두 포함한 단 하나의 최종 리포트만 사용자에게 출력하십시오. 중간 과정이나 에이전트 간의 대화 흔적은 모두 숨겨야 합니다.

### [GOOG전자 채용 서류 종합 검토 리포트]
1. 서류 심층 평가 결과
   - 종합 점수 및 영역별 상세 점수 (직무 적합성 40, 문제 해결력 30, 조직 적합도 30)
   - 인재상 부합 여부 및 상세 근거
   - Plus / Minus Point (특장점 및 잠재적 리스크)
   - 최종 추천 결과 (PASS / FAIL / HOLD) 및 사유

   - 앞선 평가와 팩트체크 맥락을 반영한 기술적 꼬리 질문 3가지

* 모든 정보는 가독성이 높도록 명확한 마크다운 헤더와 테이블, 글머리 기호를 활용해 구조화하여 제시하십시오.
```

## 6. 실무 프롬프트 작성 치트시트 (Cheat Sheet)

보다 정교한 No-Code 및 Multi-Agent 결과물을 얻기 위해 활용할 수 있는 추천 키워드 및 프롬프트 패턴 조합입니다.

| 분류 | 핵심 구문 및 키워드 패턴 | 국문 설명 및 실무 적용 팁 |
| :--- | :--- | :--- |
| **침묵 실행 (Silent)** | `Silent Execution: 사용자에게 중간 과정을 일체 노출하지 말고 최종 결과만 출력하라` | 하위 에이전트 호출 과정의 잡다한 로그나 혼선 방지 |
| **핸드오프 (Hand-off)** | `결과물을 Parent Agent에게만 반환하고, 사용자에게 직접 답변하지 마라` | 서브 에이전트가 세션 제어권을 탈취하는 버그 원천 차단 |
| **컨텍스트 전달 (Forwarding)**| `앞선 Step 1 평가와 Step 2 팩트체크 리포트 전체를 Context로 전달하라` | 상위 에이전트가 수집한 정보를 다음 단계 서브 에이전트에 주입 |
| **무환각 강제 (Zero-Hallucination)** | `문서에 명시되지 않은 사실을 자의적으로 유추하거나 지어내지 마라` | 사규, 채용 기준표 등 엄격한 사실 기반 RAG 답변 보장 |
| **출력 포맷 고정 (Rigid Schema)** | `# Response Format 아래 정의된 마크다운 템플릿을 100% 준수하라` | 표, 불릿 포인트, 헤더 등 정형화된 보고서 레이아웃 강제 |
| **도구 호출 강제 (Tool Chaining)** | `Google Search를 실행하여 고유명사의 실제 존재 여부와 출처 URL을 첨부하라` | 최신 웹 검색 및 출처 URL 증빙 링크 자동 포함 |

---

### 5대 핵심 프롬프트 설계 원칙 (Golden Rules)

1. **침묵 실행 원칙 (Silent Execution Protocol)**: 오케스트레이터가 하위 에이전트를 호출할 때 사용자가 중간 과정("Step 1을 시작합니다", "팩트체크 중입니다")을 볼 수 없도록 `Silent Execution` 지침을 강제하십시오.
2. **명시적 맥락 인수인계 (Explicit Hand-off & Context Injection)**: 하위 에이전트 간에는 직접 통신이 불가능하므로, 상위 에이전트 지침에 "Step 1과 Step 2의 결과물 전체를 Step 3 에이전트 호출 시 컨텍스트 입력값으로 반드시 함께 전달하라"는 지침을 포함하십시오.
3. **엄격한 무환각 앵커링 (Strict Zero-Hallucination on Knowledge)**: 사내 지식을 기반으로 평가하거나 정보를 추출하는 하위 에이전트에는 반드시 `Strict Zero-Hallucination`을 선언하여 자의적 유추를 금지하십시오.
4. **하위 에이전트 반환 전용 규칙 (Hand-off Return Only Rule)**: 모든 Sub-Agent에 "작업이 완료되면 분석 결과를 상위 에이전트(Parent Agent)에게만 직접 반환하고, 사용자에게 인사말을 건네거나 대화를 임의로 종료하지 말 것"을 명시하십시오.
5. **정형화된 출력 템플릿 강제 (Rigid Response Schema)**: 에이전트 시스템 프롬프트 맨 하단에 `# Response Format` 섹션을 두고 마크다운 테이블, 불릿 포인트, 필수 기재 필드를 견본 형태로 고정하십시오.

### 7.2 자주 묻는 질문 (FAQ)

#### Q1. No-Code 에이전트 하나에 하위 서브 에이전트를 몇 개까지 연결할 수 있나요?
> **A:** 실무적으로는 단일 오케스트레이터당 **3개~5개 내외의 서브 에이전트**를 구성하는 것이 가장 이상적입니다. 서브 에이전트가 지나치게 많아지면 실행 지연(Latency)이 증가하고 컨텍스트 전달 과정에서 정보 압축 손실이 발생할 수 있으므로, 역할별로 명확히 분리된 정예 에이전트 구성을 권장합니다.

#### Q2. 사내 비공개 문서를 에이전트 Knowledge로 등록해도 보안상 안전한가요?
> **A:** 완벽히 안전합니다. 바인딩된 사내 문서는 Gemini Enterprise의 테넌트 보안 경계 내에서만 임베딩 및 검색되며, 모델 학습에 일체 활용되지 않습니다. 또한 에이전트를 조직에 공유하더라도 문서를 열람할 수 있는 권한은 Google Workspace의 접근 제어(ACL) 정책을 그대로 계승합니다.

#### Q3. Workflow Agent가 긴 백그라운드 작업을 수행할 때 브라우저를 계속 켜두어야 하나요?
> **A:** 아닙니다. 장시간 소요되는 워크플로우나 스케줄링된 에이전트는 서버리스 인프라에서 독립적으로 실행되며, 처리가 완료되면 **스마트 수신함(Inbox)** 및 등록된 **이메일(Gmail)**로 결과 리포트가 자동 발송되므로 브라우저를 닫아두어도 안전합니다.

#### Q4. 생성된 에이전트를 다른 팀원이 수정하지 못하도록 읽기 전용으로만 배포할 수 있나요?
> **A:** 가능합니다. 에이전트 공유 창에서 대상 사용자 그룹을 추가할 때 권한 옵션을 **'조회 가능(Can view)'**으로 설정하면, 팀원들은 에이전트를 자유롭게 실행하고 대화할 수는 있지만 에이전트의 내부 프롬프트, 도구, 모델 설정은 수정할 수 없도록 안전하게 보호됩니다.
