# 🤖 Gemini Enterprise No-Code & Workflow Agent 핸즈온 랩 가이드

본 문서는 **Gemini Enterprise App**의 내장 **Agent Designer(로우코드/노코드 에이전트 스튜디오)**를 활용하여, 복잡한 프로그래밍이나 외부 개발 프레임워크 없이도 누구나 최고 수준의 **단일 No-Code 에이전트** 및 **비즈니스 워크플로우 에이전트(Workflow Agent)**를 직접 설계·제작·스케줄링하고 조직 내에 배포할 수 있도록 구성된 실무 핸즈온 랩 가이드입니다.

Google의 최첨단 생성 AI 파운데이션 모델을 바탕으로, 비즈니스 실무자가 일상적인 마케팅 콘텐츠 제작부터 프롬프트 기반 자동 워크플로우 구축(스케줄링, 조건 분기, 인간 승인, 구글 드라이브 저장)까지 단계별로 직접 구축하고 검증하는 4가지 실전 랩 시나리오와 프롬프트 설계 지침, 현장 트러블슈팅 가이드를 제공합니다.

## 1. No-Code Agent 환경 개요 및 핵심 개념

### 1.1 No-Code Agent란 무엇인가?
**No-Code Agent**란 복잡한 소프트웨어 코딩, 백엔드 서버 구축, 외부 API 연동 없이 웹 브라우저 기반의 **직관적인 자연어 프롬프트와 그래픽 빌더 인터페이스(GUI)**만으로 목적에 특화된 AI 업무 에이전트를 직접 제작하고 실행할 수 있는 Gemini Enterprise의 핵심 기능입니다.

비즈니스 기획자, 마케터, 인사/채용 담당자, 영업 대표 등 현업 실무자 누구나 자신의 전문 업무 지식(Domain Knowledge)을 에이전트에 주입하여 즉시 활용 가능한 사내 전용 AI 팀원을 손쉽게 구축할 수 있습니다.

### 1.2 일반 챗봇(General Chat)과의 차이점

| 비교 항목 | 일반 Gemini 챗 (General Chat) | Gemini No-Code Agent |
| :--- | :--- | :--- |
| **역할 및 페르소나** | 매 세션마다 프롬프트로 역할을 재부여해야 함 | 에이전트 생성 시 정의된 전문 역할과 비즈니스 룰이 **영구 고정**됨 |
| **지식 베이스 (Knowledge)** | 사용자가 대화 세션마다 관련 문서를 수동 업로드 | 사내 정책, 평가 기준표, 매뉴얼이 **에이전트에 사전 바인딩**됨 |
| **도구 활용 (Tools)** | 사용자가 수동으로 검색/커넥터 툴을 지정 | Google Search, Enterprise Connectors를 **에이전트가 자율 연쇄 호출** |
| **출력 형식 (Format)** | 일반적인 서술형 텍스트 응답 | 사전에 정의된 **표, 평가표, 리포트 템플릿 서식을 100% 준수** |
| **실행 방식** | 사용자의 즉각적인 1회성 입력에만 반응 | **주기적 스케줄(Cron) 자동 실행** 및 백그라운드 비동기 처리 지원 |
| **협업 및 거버넌스** | 개인 세션에 완전히 격리 | 조직/부서 단위로 **공유 및 중앙 권한 통제** 가능 |

### 1.3 핵심 에이전트 구축 패러다임

```mermaid
graph TD
    subgraph "1. No-Code Single Agent"
        A[User Prompt] --> B[Single Agent<br>Role + Knowledge + Tools]
        B --> C[Direct Structured Output]
    end

    subgraph "2. Workflow Agent"
        J[Schedule: 매일 09:00] --> K[1단계: AI 시장 뉴스 수집 & 위협 수준 분석]
        K --> L{2단계: 조건 분기<br>위협 수준 High vs Else}
        L -->|High: 고위협| M[3단계: 홍보 지침 입력 & 사람 필수 승인]
        L -->|Else: 일반| N[3단계: 질문1 입력 & 즉시 자동 완성]
        M --> O[💾 최종 브리핑 구글 드라이브 저장]
        N --> O
    end
```

1. **No-Code 단일 에이전트 (Single Agent)**: 자연어 대화 또는 노드 빌더를 통해 생성되며, 특정 반복 업무(예: 소셜 미디어 게시물 작성, 역사 인사이트 도출)를 완결하는 기본 에이전트.
2. **워크플로우 에이전트 (Workflow Agent)**: 프롬프트 지시를 통해 스케줄 트리거, 데이터 수집, 조건 분기(Branching), 인간 입력 및 필수 승인(Review), 구글 드라이브 파일 저장 액션으로 이어지는 다단계 자동화 파이프라인을 구축하는 에이전트.

### 1.4 4가지 핵심 기능 검증 매트릭스

| 모듈 | 기능 영역 | 핵심 검증 목표 | 주요 활용 모델 및 도구 |
| :--- | :--- | :--- | :--- |
| **Lab 1** | **Prompt-based Agent** | 자연어 프롬프트 1문장으로 소셜 마케팅 문구 생성 에이전트 자동 구축 | Gemini 3.5 Flash (자연어 모드) |
| **Lab 2** | **Builder-based Agent** | 비주얼 빌더를 통한 맞춤형 지침 수동 구성 및 Google Search 도구 연동 | Gemini 3.5 Flash + Google Search |
| **Lab 3** | **Sharing & Scheduling** | 조직 사용자 그룹 대상 에이전트 권한 공유 및 백그라운드 자동 실행 스케줄링 | Agent Scheduler (Active Cron) |
| **Lab 4** | **Prompt-based Workflow Agent** | 프롬프트 기반 뉴스 분석·위협 수준 분기·인간 승인·구글 드라이브 저장 파이프라인 구축 | Gemini 3.5 Flash/Pro + Search + Google Drive Action |

## 2. 실습 환경 사전 준비 및 Agent Designer 인터페이스

### 2.1 사전 준비 사항 (Prerequisites)
1. **Gemini Enterprise 전용 계정**: 실습용 Google Workspace 또는 Cloud Identity 계정으로 로그인합니다.
2. **라이선스 및 권한 확인**:
   - Gemini Enterprise 활성화 라이선스 부여 여부 확인
   - Agent Designer 에이전트 생성, 편집, 공유 및 스케줄링 권한 확인
   - Google Drive 및 Google Search 도구 사용 권한 확인

### 2.2 Agent Designer 인터페이스 레이아웃 및 조작법

- **Agent 메뉴 진입**: 좌측 메인 네비게이션 바에서 **Agents** 아이콘을 클릭합니다.
- **새 에이전트 생성 버튼**:
  - **자연어 프롬프트 모드**: 하단 텍스트 입력창에 에이전트의 역할, 파이프라인 단계, 조건 분기, 도구 연동을 서술하면 AI가 이름, 설명, 지침, Flow 뷰를 자동으로 완벽히 구성합니다.
  - **빌더로 진행 (Proceed with Builder)**: 노드 기반 비주얼 캔버스에서 이름, 설명, 모델, 지식 문서, 도구, 시스템 지침을 정밀하게 수동 세팅합니다.
- **에이전트 노드 속성 패널**:
  - **Name & Description**: 에이전트의 명칭 및 역할 요약
  - **Model 선택**: 작업의 성격에 따라 적합한 모델 지정
  - **Knowledge (지식)**: Google Drive 내 문서 또는 PDF/문서 파일을 바인딩하여 RAG 기반 사내 지식 고정
  - **Connectors / Tools**: `Google Search`, `Google Drive (Save File Action)`, `Approval Action` 등 도구 활성화
  - **원시 텍스트 모드 (Raw Text Mode)**: 복잡한 비즈니스 룰과 시스템 프롬프트를 마크다운 구조로 직접 작성
  - **시작 프롬프트 (Starting Prompts)**: 사용자가 대화 시작 시 클릭할 수 있는 추천 프롬프트 칩(Prompt Chips) 등록
- **Flow 뷰 (Workflow Flowchart)**: 트리거, 검색 노드, 조건 분기 노드, 인간 입력 필드, 승인 게이트, 구글 드라이브 저장 액션 간의 연결 관계를 시각적 흐름도로 조망하고 검증합니다.

### Lab 2. 빌더(Builder) 기반 맞춤형 에이전트 수동 구성 & 검색 도구 연동

자연어 자동 생성 방식의 한계를 넘어, **빌더(Builder)**를 통해 시스템 프롬프트(원시 텍스트 모드), 실시간 웹 검색(Google Search) 도구, 그리고 심층 분석 로직을 체계적으로 결합한 **"온고지신(溫故知新) 역사 인사이트 분석 에이전트"**를 구축합니다.

사용자가 특정 역사적 사건이나 정책에 대해 질문하면, 구글 검색으로 사실관계를 정밀 검증한 뒤 현재 대한민국이 직면한 주요 과제(정치·행정, 경제·산업, 외교·안보·사회)에 적용할 수 있는 실천적 시사점과 정책 제언을 도출합니다.

#### 1) 실행 환경 설정
1. **Agents** 메뉴 ➔ **새 에이전트** 클릭.
2. 대화창 하단의 **"빌더로 진행(Proceed with Builder)"**을 선택합니다.

<img style="border: 1px solid #e0e0e0; border-radius: 6px; box-shadow: 0 2px 5px rgba(0,0,0,0.05);" src="resources/img/lab2-1.png" width="586">

#### 2) 에이전트 노드 속성 구성
- **Name (이름):** `온고지신(溫故知新) 역사 인사이트 분석 에이전트`
- **Description (설명):**
  ```text
  질문받은 역사적 사건의 배경과 전개 결과를 실시간 검색으로 정확히 파악하고, 이를 현대 대한민국의 정치·경제·사회·외교적 현실에 투영하여 실천적 시사점과 정책적 제언을 도출하는 역사 전략 분석 비서입니다.
  ```

#### 3) Instruction 구성
요청사항(Instructions) 창에서 아래의 마크다운 지침 템플릿을 입력합니다:

```text
# Role & Goal
당신은 역사적 사건과 교훈을 깊이 있게 고찰하여 현대 대한민국의 당면 과제에 실천적인 통찰을 제공하는 '역사 전략 분석가(History & Strategic Insight Analyst)'입니다.
사용자가 특정 역사적 사건, 인물, 정책, 제도에 대해 질문하면, 구글 검색(Google Search) 도구를 활용하여 정확한 역사적 사실관계를 검증한 뒤, 이를 오늘날 대한민국의 정치, 경제, 산업, 사회, 외교안보 환경과 입체적으로 비교 분석하여 구체적이고 실행 가능한 시사점과 제언을 도출합니다.

---

# Core Workflow & Tool Use Guidelines

### Step 1: 역사적 사실 확인 및 사료 검증 (Google Search 연동)
- 질문받은 역사적 사건, 인물, 정책의 핵심 키워드를 추출하여 Google Search 도구를 실행합니다.
- 다음 핵심 정보를 객관적 사료와 팩트 기반으로 수집합니다:
  1. 사건의 역사적 배경 및 발생 원인
  2. 주요 전개 과정 및 핵심 정책/결정 내용
  3. 사건의 최종 결과 및 역사적 평가 (성공 요인 및 한계점)
- 모호하거나 논쟁적인 역사적 사실은 공신력 있는 백과사전 및 학술적 정설을 기반으로 서술합니다.

### Step 2: 현대 대한민국과의 상관관계 및 문제의식 매핑 (Contemporary Mapping)
- 해당 역사적 사건의 본질(갈등 구조, 자원 배분, 기술 혁신, 외교적 역학 등)을 파악합니다.
- 현재 대한민국이 직면한 유사 현안(예: 저출생 고령화, 조세 형평성, 첨단 기술 패권 경쟁, 에너지 안보, 글로벌 공급망 재편 등)과 일대일로 매핑하여 비교 분석합니다.

### Step 3: 구조화된 시사점 및 미래 제언 도출
- 정책 입안자(정부), 기업 경영자(산업계), 일반 시민(사회) 관점에서 적용 가능한 3대 실천 시사점을 도출합니다.
- 아래 명시된 엄격한 출력 서식(Response Format)을 100% 준수하여 한국어로 작성하십시오.
```

### Lab 4. 프롬프트 기반 워크플로우 에이전트(Workflow Agent) 자동 생성 및 최종 브리핑 구글드라이브에 저장

자연어 프롬프트 지시만으로 **매일 오전 9시 스케줄 트리거 ➔ 실시간 AI 뉴스 수집 및 위협 수준 분석 ➔ 조건 분기(High vs Else) ➔ 담당자 입력 및 사람의 필수 승인(Review) ➔ 최종 브리핑 구글드라이브에 저장**으로 이어지는 완결형 엔터프라이즈 워크플로우 파이프라인을 자동 생성하고 검증합니다.

#### 1) 실행 환경 설정
1. 좌측 네비게이션 바에서 **Agents** 메뉴를 클릭합니다.
2. 우측 상단의 **새 에이전트(New Agent) > Workflow Agent**를 클릭합니다.
3. 초기 **대화창 모드(Prompt 모드)**에서 시작합니다. (수동으로 노드를 일일이 배치하지 않고, 정교한 자연어 프롬프트 지시를 통해 에이전트 디자이너가 파이프라인 전체를 자동으로 구성하도록 합니다.)

#### 2) 워크플로우 에이전트 생성 프롬프트 입력
대화창의 입력 옴니바에 아래의 구조화된 프롬프트를 복사하여 입력하고 전송합니다:

> 💬 **워크플로우 에이전트 생성 프롬프트:**
> ```text
> 매일 오전 9시에 자동 실행되는 'AI 시장 뉴스 분석 및 경영진 브리핑 워크플로우 에이전트'를 만들어줘.
> 이 워크플로는 최신 AI 시장 뉴스를 분석해 경영진 브리핑을 작성하며, 총 3단계로 진행돼:
> 
> 1. 데이터 수집 및 분석:
> - Google 검색 도구를 활용해 지난 24시간 동안의 'AI 규제' 및 '기업 AI 도입' 뉴스를 실시간으로 수집해.
> - 수집된 정보를 바탕으로 시장 요약, 주요 핵심 주제, 그리고 기업에 미치는 위협 수준('High' 또는 'Low')을 자동 도출해.
> 
> 2. 조건 분기:
> - 분석된 위협 수준에 따라 작업을 'High(고위협)' 트랙과 'Else(일반)' 트랙 두 가지 경로로 자동 전환해.
> 
> 3. 트랙별 실행, 승인 및 구글 드라이브 저장:
> • High 트랙:
>   - 담당자에게 장문의 '홍보 대응 전략 지침' 입력을 요청해.
>   - 담당자가 입력한 지침과 시장 요약을 통합하여 완성도 높은 전문 브리핑 초안을 작성해.
>   - 리스크 관리를 위해 사람의 필수 승인(Review/Approval) 절차를 거치도록 해.
>   - 승인이 완료되면 최종 브리핑 결과를 로그인한 사용자의 구글드라이브에 즉시 저장해.
> • Else 트랙:
>   - 사용자에게 간단한 '질문 1' 텍스트 입력을 받아.
>   - 별도의 승인 절차 없이 시장 요약만으로 일반 브리핑 초안을 즉시 자동 완성해.
>   - 완성된 최종 일반 브리핑 결과를 로그인한 사용자의 구글드라이브에 즉시 저장해.
> 
> 전체적인 최종 처리 결과는 사용자가 구글 드라이브에서 확인할수 있도록 로그인한 계정의 구글 드라이브에 저장해줘. 
> 에이전트 구성 및 모든 안내 문구, 질문 폼, 브리핑 양식 작성시 언어는 완벽한 한국어로 작성해줘.
> ```

## 5. 실무 프롬프트 작성 치트시트 (Cheat Sheet)

보다 정교한 No-Code 및 Workflow Agent 결과물을 얻기 위해 활용할 수 있는 추천 키워드 및 프롬프트 패턴 조합입니다.

| 분류 | 핵심 구문 및 키워드 패턴 | 국문 설명 및 실무 적용 팁 |
| :--- | :--- | :--- |
| **스케줄 트리거 (Schedule)** | `매일 오전 OO시에 자동 실행되는 워크플로우를 만들어줘` | 자동 주기 실행을 위한 스케줄 트리거 노드 생성 |
| **조건 분기 (Branching)** | `분석된 위협 수준에 따라 'High'와 'Else' 경로로 자동 전환하라` | 수집 데이터 분석 결과에 따른 다분기 로직 구성 |
| **인간 검토 및 승인 (HITL)** | `전문 브리핑 초안을 작성한 후 사람의 필수 승인(Review) 절차를 거쳐라` | 대외 공유 전 사람의 확인/승인 게이트 배치 (Human-in-the-loop) |
| **파일 저장 액션 (Drive Action)** | `최종 처리 결과를 로그인한 사용자의 구글 드라이브에 저장해줘` | 완성된 리포트를 Google Drive에 자동 문서로 저장 |
| **무환각 강제 (Zero-Hallucination)** | `문서에 명시되지 않은 사실을 자의적으로 유추하거나 지어내지 마라` | 사규, 가이드라인 등 엄격한 사실 기반 RAG 답변 보장 |
| **출력 포맷 고정 (Rigid Schema)** | `# Response Format 아래 정의된 마크다운 템플릿을 100% 준수하라` | 표, 불릿 포인트, 헤더 등 정형화된 보고서 레이아웃 강제 |
| **도구 호출 강제 (Tool Chaining)** | `Google Search를 실행하여 실시간 최신 뉴스와 출처 URL을 포함하라` | 최신 웹 검색 연동 및 근거 링크 자동 포함 |

### 5대 핵심 프롬프트 설계 원칙 (Golden Rules)

1. **명확한 스케줄 및 트리거 정의 (Clear Schedule Triggers)**: 워크플로우를 자동으로 실행할 주기(매일, 특정 요일, 시간)를 프롬프트 서두에 명확히 정의하십시오.
2. **조건 분기(Branching) 기준 명시**: 데이터 분석 결과에 따라 갈라지는 분기 조건(예: 'High' vs 'Else')과 각 경로별 실행할 세부 액션을 구체적으로 기술하십시오.
3. **인간 개입(Human-in-the-loop) 승인 게이트 배치**: 리스크가 높은 작업이나 경영진 보고 전에는 반드시 사람의 필수 검토(Review & Approval) 단계를 거치도록 지시하십시오.
4. **외부 도구 및 저장 액션 연동 (Tool & Storage Integration)**: 실시간 검색(Google Search) 및 결과 저장 대상(Google Drive)을 명시하여 완결된 엔드투엔드 파이프라인을 구성하십시오.
5. **정형화된 출력 템플릿 강제 (Rigid Response Schema)**: 에이전트 시스템 프롬프트 맨 하단에 `# Response Format` 섹션을 두고 마크다운 테이블, 불릿 포인트, 필수 기재 필드를 견본 형태로 고정하십시오.

## 6. 트러블슈팅 및 운영 권장사항 (FAQ)

### 6.1 현장 트러블슈팅 매트릭스

| 증상 및 오류 현상 | 발생 원인 | 권장 조치 및 해결 방법 |
| :--- | :--- | :--- |
| **스케줄러가 설정 시간에 실행되지 않음** | 스케줄 활성화(Active) 누락 및 권한 만료 | 1. Schedule 탭에서 상태가 **Active**인지 확인<br>2. 에이전트에 바인딩된 OAuth 커넥터(Google Drive, Search)의 인증 세션이 만료되지 않았는지 재승인 |
| **조건 분기(High vs Else)가 정상 동작하지 않음** | 분류 기준 모호성 또는 출력 키 미일치 | 프롬프트에 `위협 수준을 'High' 또는 'Low' 중 하나로만 명확히 도출하라`고 제약 조건을 강화 |
| **구글 드라이브에 결과 파일이 생성되지 않음** | Google Drive 권한 미승인 또는 액션 노드 누락 | 워크플로우 최초 실행 시 Google Drive 접근 승인 팝업을 확인하고 권한을 허용했는지 확인 |
| **지식 문서(Knowledge)를 무시하고 일반 상식 답변** | RAG 바인딩 오류 또는 지침 우선순위 미지정 | 에이전트 노드에 지식 문서가 정상 첨부되었는지 확인하고, 프롬프트 서두에 `"첨부된 지식 문서를 절대적인 1차 기준으로 삼아라"`고 명시 |

### 6.2 자주 묻는 질문 (FAQ)

#### Q1. Workflow Agent가 긴 백그라운드 작업을 수행할 때 브라우저를 계속 켜두어야 하나요?
> **A:** 아닙니다. 장시간 소요되는 워크플로우나 스케줄링된 에이전트는 서버리스 인프라에서 독립적으로 실행되며, 처리가 완료되면 **스마트 수신함(Inbox)** 및 연동된 **Google Drive**로 결과 리포트가 안전하게 저장되므로 브라우저를 닫아두어도 안전합니다.

#### Q2. 사내 비공개 문서를 에이전트 Knowledge로 등록해도 보안상 안전한가요?
> **A:** 완벽히 안전합니다. 바인딩된 사내 문서는 Gemini Enterprise의 테넌트 보안 경계 내에서만 임베딩 및 검색되며, 모델 학습에 일체 활용되지 않습니다. 또한 에이전트를 조직에 공유하더라도 문서를 열람할 수 있는 권한은 Google Workspace의 접근 제어(ACL) 정책을 그대로 계승합니다.

#### Q3. 생성된 에이전트를 다른 팀원이 수정하지 못하도록 읽기 전용으로만 배포할 수 있나요?
> **A:** 가능합니다. 에이전트 공유 창에서 대상 사용자 그룹을 추가할 때 권한 옵션을 **'조회 가능(Can view)'**으로 설정하면, 팀원들은 에이전트를 자유롭게 실행하고 대화할 수는 있지만 에이전트의 내부 프롬프트, 도구, 모델 설정은 수정할 수 없도록 안전하게 보호됩니다.

#### Q4. 워크플로우의 승인(Review) 요청은 어디서 확인하고 진행하나요?
> **A:** 워크플로우 실행 중 Review 노드에 도달하면 대화 화면 및 스마트 수신함에 승인 대기 알림 카드가 생성됩니다. 내용 검토 후 **[승인(Approve)]** 또는 **[반려(Reject)]** 버튼을 클릭하면 다음 파이프라인 단계(예: 구글 드라이브 저장)가 자동으로 이어서 진행됩니다.
