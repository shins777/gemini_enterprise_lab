## 1. No-Code Agent 환경 개요 및 핵심 개념

### 1.1 No-Code Agent란 무엇인가?
**No-Code Agent**란 복잡한 소프트웨어 코딩, API 연동 개발, 인프라 배포 절차 없이, 웹 브라우저 기반의 **직관적인 자연어 프롬프트와 그래픽 빌더 인터페이스(GUI)**만으로 목적에 특화된 AI 업무 에이전트를 직접 제작하고 실행할 수 있는 Gemini Enterprise의 핵심 기능입니다.

비즈니스 기획자, 마케터, 인사/채용 담당자, 영업 대표 등 현업 실무자 누구나 자신의 전문 업무 지식(Domain Knowledge)을 시스템에 주입하여 즉시 활용 가능한 사내 전용 AI 팀원을 구축할 수 있습니다.

### 1.2 일반 챗봇(General Chat)과의 차이점

| 비교 항목 | 일반 Gemini 챗 (General Chat) | Gemini No-Code Agent |
| :--- | :--- | :--- |
| **역할 및 페르소나** | 매 세션마다 프롬프트로 지시해야 함 | 에이전트 생성 시 정의된 전문 역할과 비즈니스 룰이 **영구 고정**됨 |
| **지식 베이스 (Knowledge)** | 사용자가 세션마다 파일을 매번 업로드 | 사내 정책, 가이드라인, 매뉴얼 문서가 **지식 베이스로 사전 바인딩**됨 |
| **도구 활용 (Tools)** | 사용자가 수동으로 검색/커넥터를 지정 | Google Search, MCP 도구, 사내 커넥터를 **에이전트가 자율적/연쇄 호출** |
| **출력 형식 (Format)** | 일반적인 대화형 응답 | 사전에 설계된 **표, 보고서 템플릿 등 정형화된 서식을 100% 준수** |
| **실행 방식** | 사용자의 즉각적인 입력에만 반응 | **주기적 스케줄(Cron) 자동 실행** 및 백그라운드 비동기 처리 지원 |
| **협업 및 거버넌스** | 개인 세션에 격리 | 조직/부서 단위로 **공유 및 중앙 권한 통제** 가능 |

### 1.3 3가지 에이전트 구축 아키텍처

```mermaid
graph TD
    subgraph "1. No-Code Single Agent"
        A[User Prompt] --> B[Single Agent<br>Role + Knowledge + Tools]
        B --> C[Direct Structured Output]
    end

    subgraph "2. Workflow Agent"
        J[Schedule: 매일 09:00] --> K[1단계: AI 시장 뉴스 수집 & 위협 수준 분석]
        K --> L{2단계: 조건 분기<br>위협 수준 High vs Else}
        L -->|High: 고위협| M[3단계: 홍보 지침 입력 & 사람 필수 승인]
        L -->|Else: 일반| N[3단계: 질문1 입력 & 즉시 자동 완성]
        M --> O[📧 최종 브리핑 이메일 자동 발송]
        N --> O
    end

    subgraph "3. Multi-Agent System"
        D[User Request & File] --> E[Root Orchestrator Agent]
        E -->|Call Step 1| F[Sub-Agent 1: Evaluator]
        F -->|Score & Risk| E
        E -->|Call Step 2| G[Sub-Agent 2: Fact-Checker]
        G -->|Fact Report & URL| E
        E -->|Call Step 3 + Context 1&2| H[Sub-Agent 3: Question Designer]
        H -->|Targeted Questions| E
        E -->|Synthesize| I[Single Consolidated Report]
    end
```

1. **No-Code 단일 에이전트 (Single Agent)**: 자연어 대화 또는 노드 빌더를 통해 생성되며, 특정 반복 업무(예: 소셜 미디어 게시물 작성, 사내 식단 안내)를 완결하는 기본 에이전트.
2. **워크플로우 에이전트 (Workflow Agent)**: 프롬프트 지시를 통해 스케줄 트리거, 데이터 수집, 조건 분기(Branching), 인간 입력 및 필수 승인(Review), 이메일 발송 액션으로 이어지는 다단계 자동화 파이프라인을 구축하는 에이전트.
3. **계층형 멀티 에이전트 (Hierarchical Multi-Agent System)**: 상위 오케스트레이터(Root Agent)가 하위 전문 에이전트(Sub-Agents)들을 지정된 순서대로 호출하고, 중간 산출물을 다음 단계 에이전트에게 맥락(Context)으로 인수인계(Hand-off)하여 최종 단일 종합 보고서를 합성하는 엔터프라이즈 시스템.

## 2. Agent Designer 실습 환경 사전 준비 및 인터페이스

### 2.1 사전 준비 사항 (Prerequisites)
1. **Gemini Enterprise 전용 계정**: 실습용 Google Workspace 또는 Cloud Identity 계정 로그인
2. **권한 및 커넥터 확인**:
   - Agent Designer 생성 및 편집 권한 확인
   - Gmail(이메일 발송) 커넥터 및 Google Search 도구 사용 권한
3. **실습용 사전 준비 파일 (Multi-Agent 실습용)**:
   - `2026년 GOOG전자 서류전형 평가 가이드라인.pdf` (평가 기준 지식 베이스)
   - `GOOG전자 입사지원서_이OO.pdf` (테스트용 지원서 샘플 1)
   - `GOOG전자 입사지원서_김OO.pdf` (테스트용 지원서 샘플 2)

### 2.2 Agent Designer 인터페이스 레이아웃 및 조작법

- **Agent 메뉴 진입**: 좌측 메인 네비게이션 바에서 **Agents** 아이콘을 클릭합니다.
- **새 에이전트 생성 버튼**:
  - **자연어 프롬프트 모드**: 입력창에 에이전트의 역할과 요건을 서술하면 AI가 이름, 설명, 지침, 플로우를 자동 구성합니다.
  - **빌더로 진행 (Proceed with Builder)**: 노드 기반 비주얼 캔버스에서 이름, 설명, 모델, 지식 문서, 도구, 시스템 지침을 정밀하게 수동 세팅합니다.
- **에이전트 노드 편집 속성**:
  - **Name & Description**: 에이전트의 명칭 및 역할 요약
  - **Model 선택**: 작업의 복잡도에 따라 Gemini Flash 또는 Pro 모델 지정
  - **Knowledge (지식)**: Google Drive 내 문서 또는 로컬 파일 바인딩 (RAG 기반 지식 고정)
  - **Connectors / Tools**: Google Search, Enterprise Connectors, MCP 도구 선택
  - **원시 텍스트 모드 (Raw Text Mode)**: 상세 시스템 프롬프트(Instruction)를 마크다운 구조로 직접 작성
  - **시작 프롬프트 (Starting Prompts)**: 사용자가 대화 시작 시 클릭할 수 있는 추천 프롬프트 칩(Prompt Chips) 등록
- **Flow 뷰 (Workflow Flowchart)**: 트리거, 검색 노드, 조건 분기 노드, 인간 입력 필드, 승인 게이트, 이메일 발송 액션 간의 연결 관계를 시각적 흐름도로 조망하고 검증합니다.

### Lab 1. 대화형 프롬프트 기반 에이전트 자동 생성

자연어 프롬프트 한 문장으로 **소셜 미디어 마케팅 콘텐츠 제작 에이전트**의 기본 골격을 단 몇 초 만에 자동으로 생성하고 검증합니다.

#### 1) 실행 환경 설정
- 좌측 네비게이션 바에서 **Agents** 메뉴 클릭 ➔ **새 에이전트(New Agent)**를 클릭합니다.
- 자연어 생성 대화창 모드로 시작합니다.

#### 2) 실습 프롬프트
> 💬 **에이전트 생성 명령 프롬프트:**
> ```text
> 뉴스 링크를 입력 받아서 Social Media 포스팅할 게시물 문구를 생성하는 에이전트를 만들어줘.
> 포스팅할 문구는 간략한 한 줄 문장과 bullet point 5개를 생성하고 추천 Hashtag도 포함해줘.
> ```

#### 3) 빌더 확인 및 테스트
1. AI가 생성한 에이전트 이름, 설명, 요청사항(Instruction)을 검토합니다.
2. 상단의 **Flow 뷰**를 클릭하여 생성된 워크플로우 구조를 시각적으로 확인합니다.
3. 우측 상단의 **생성(Create)** 버튼을 클릭하여 에이전트를 저장합니다.
4. 테스트 대화창에 실제 뉴스 기사 URL을 전달하여 동작을 검증합니다:
   > 💬 **테스트 입력 프롬프트:**
   > ```text
   > 이 뉴스 링크로 소셜 미디어 게시물을 만들어줘: https://live.lge.co.kr/2604-lg-sales2026/
   > ```

#### 4) 검증 포인트
- [ ] 입력된 기사의 핵심 내용을 관통하는 매력적인 한 줄 요약 문장이 도출되는가?
- [ ] 5개의 글머리 기호(Bullet Points)로 핵심 팩트가 일목요연하게 정리되는가?
- [ ] 관련성이 높은 트렌디한 해시태그(#)들이 정확히 추천되는가?

### Lab 2. 빌더(Builder) 기반 맞춤형 에이전트 수동 구성 & 검색 도구 연동

자연어 생성 방식의 한계를 넘어, **빌더(Builder)**를 통해 시스템 프롬프트(원시 텍스트 모드), 실시간 웹 검색(Google Search) 도구, 그리고 심층 분석 로직을 체계적으로 결합한 **"온고지신(溫故知新) 역사 인사이트 분석 에이전트"**를 구축합니다.

사용자가 특정 역사적 사건, 인물, 정책, 제도에 대해 질문하면, 구글 검색을 통해 역사적 사실관계를 정확히 검증한 후 사건의 본질을 분석하여 현재 대한민국이 직면한 주요 과제(정치·행정, 경제·산업, 외교·안보·사회)에 적용할 수 있는 실천적 시사점과 미래 정책 제언을 도출합니다.

#### 1) 실행 환경 설정
- **Agents** 메뉴 클릭 ➔ **새 에이전트** 클릭 ➔ **"빌더로 진행(Proceed with Builder)"**을 선택합니다.

#### 2) 에이전트 노드 속성 구성
- **Name (이름):** `온고지신(溫故知新) 역사 인사이트 분석 에이전트`
- **Description (설명):**
  ```text
  질문받은 역사적 사건의 배경과 전개 결과를 실시간 검색으로 정확히 파악하고, 이를 현대 대한민국의 정치·경제·사회·외교적 현실에 투영하여 실천적 시사점과 정책적 제언을 도출하는 역사 전략 분석 비서입니다.
  ```
- **Model:** `Gemini 3.5 Flash`
- **Connectors / Tools:** `Google Search` 활성화
- **Starting Prompts (대화 시작문):**
  - `조선 후기 대동법(大同法) 시행 과정과 현대 조세·복지 정책에 주는 시사점`
  - `1970년대 오일 쇼크(석유 파동) 당시의 대응과 현재 우리나라 에너지 안보 시사점`
  - `로마 제국의 도로망 구축 정책이 현대 한국의 AI·모빌리티 고속도로에 주는 교훈`
  - `임진왜란 직전 조선의 외교·국방 정세와 현재 한반도 주변 안보 환경 비교`

#### 3) 원시 텍스트 모드 (Raw Instruction) 작성
- 요청사항(Instructions) 창에서 **"원시 텍스트 모드 전환"**을 클릭하고 아래의 마크다운 템플릿을 입력합니다:

```text
# Role & Goal
당신은 역사적 사건과 교훈을 깊이 있게 고찰하여 현대 대한민국의 당면 과제에 실천적인 통찰을 제공하는 '역사 전략 분석가(History & Strategic Insight Analyst)'입니다.
사용자가 특정 역사적 사건, 인물, 정책, 제도에 대해 질문하면, 구글 검색(Google Search) 도구를 활용하여 정확한 역사적 사실관계를 검증한 뒤, 이를 오늘날 대한민국의 정치, 경제, 산업, 사회, 외교안보 환경과 입체적으로 비교 분석하여 구체적이고 실행 가능한 시사점과 제언을 도출합니다.

---

# Core Workflow & Tool Use Guidelines

### Step 1: 역사적 사실 확인 및 사료 검증 (Google Search 연동)
- 질문받은 역사적 사건, 인물, 정책의 핵심 키워드를 추출하여 Google Search 도구를 실행합니다.
- 다음 핵심 정보를 객관적 사료와 팩트 기반으로 수집합니다:
  1. 사건의 역사적 배경 및 발생 원인
  2. 주요 전개 과정 및 핵심 정책/결정 내용
  3. 사건의 최종 결과 및 역사적 평가 (성공 요인 및 한계점)
- 모호하거나 논쟁적인 역사적 사실은 공신력 있는 백과사전 및 학술적 정설을 기반으로 서술합니다.

### Step 2: 현대 대한민국과의 상관관계 및 문제의식 매핑 (Contemporary Mapping)
- 해당 역사적 사건의 본질(본질적 갈등 구조, 자원 배분, 기술 혁신, 외교적 역학 등)을 파악합니다.
- 현재 대한민국이 직면한 유사 현안(예: 저출생 고령화, 조세 형평성, 첨단 기술 패권 경쟁, 에너지 안보, 글로벌 공급망 재편 등)과 일대일로 매핑하여 비교 분석합니다.

### Step 3: 구조화된 시사점 및 미래 제언 도출
- 단순한 역사 요약에 그치지 않고, 정책 입안자(정부), 기업 경영자(산업계), 일반 시민(사회) 관점에서 적용 가능한 3대 실천 시사점을 도출합니다.
- 아래 명시된 엄격한 출력 서식(Response Format)을 100% 준수하여 한국어로 작성하십시오.
```

### Lab 3. 에이전트 조직 공유 및 자동 실행 스케줄링

완성된 에이전트를 조직(부서/전사)에 배포하여 팀원들과 공유하고, 매일 특정 시간에 스스로 실행되어 보고서를 생성하도록 **자동 스케줄러(Scheduler)**를 설정합니다.

#### 1) 조직 내 에이전트 공유 (Agent Sharing)
1. **Agents** 메뉴로 이동하여 생성된 에이전트 카드의 우측 더보기(`...`) 메뉴 ➔ **공유(Share)**를 클릭합니다.
2. 대상 사용자 그룹(예: `user_group@ge-workshop.explore-ai.com` 또는 사내 부서 그룹)을 추가합니다.
3. 권한(조회 가능 / 편집 가능)을 설정한 후 **완료**를 클릭합니다.
4. 좌측 메뉴의 **"조직의 에이전트(Organization Agents)"** 탭에 해당 에이전트가 노출되고 다른 팀원이 즉시 호출할 수 있는지 확인합니다.

#### 2) 에이전트 자동 실행 스케줄링 (Agent Scheduling)
1. 등록한 에이전트를 클릭하여 **Agent Designer** 편집 화면으로 진입합니다.
2. 상단 탭에서 **Schedule**을 클릭하고 **"Add Schedule"**을 선택합니다.
3. 실행 시간 설정:
   - 실무 운영 시: 매일 평일 오전 08:30 (Cron 또는 GUI 시간 지정)
   - 실습 검증 시: 현재 시간 기준 약 2분 뒤로 설정
4. **Preview** 버튼을 눌러 스케줄 트리거 시 에이전트가 의도대로 실행되는지 미리 확인합니다.
5. **Update**를 눌러 스케줄 상태를 **Active**로 활성화합니다.
6. 약 2분 후 **Chat History**를 새로고침하여 백그라운드에서 스케줄러가 에이전트를 자동 실행하고 일일 리포트를 정상 작성했는지 로그를 확인합니다.

#### 3) 검증 포인트
- [ ] 조직의 에이전트 목록에서 동료가 생성한 에이전트를 검색 및 실행할 수 있는가?
- [ ] 브라우저를 닫아둔 상태에서도 설정된 시간에 에이전트가 백그라운드 자동 실행되는가?

## 4. Workflow Agent 구축 및 비동기 자동화 실습 (1 Module)

---

### Lab 4. 프롬프트 기반 워크플로우 에이전트(Workflow Agent) 자동 생성 및 이메일 발송 연동

자연어 프롬프트 지시만으로 **매일 오전 9시 스케줄 트리거 ➔ 실시간 AI 뉴스 수집 및 위협 수준 분석 ➔ 조건 분기(High vs Else) ➔ 담당자 입력 및 사람의 필수 승인(Review) ➔ 최종 브리핑 이메일 발송**으로 이어지는 완결형 엔터프라이즈 워크플로우 파이프라인을 자동 생성하고 검증합니다.

```mermaid
graph TD
    Trigger["⏰ 스케줄 트리거<br>(매일 오전 09:00 자동 실행)"] --> Stage1["1단계: 데이터 수집 및 분석<br>(Google 검색: 'AI 규제' & '기업 AI 도입')"]
    Stage1 --> Eval["위협 수준 자동 판정<br>('High' vs 'Low')"]
    
    Eval -->|조건 분기: High (고위협)| HighTrack["2단계 (High 트랙):<br>담당자에게 '홍보 대응 전략 지침' 입력 요청"]
    HighTrack --> HighDraft["시장 요약 + 전략 지침 통합<br>전문 브리핑 초안 작성"]
    HighDraft --> HumanReview{"3단계: 사람의 필수 승인<br>(Review / Approval 게이트)"}
    HumanReview -->|승인 완료| EmailHigh["📧 최종 브리핑 이메일 자동 발송<br>(경영진 및 담당자 수신)"]

    Eval -->|조건 분기: Else (일반)| LowTrack["2단계 (Else 트랙):<br>간단한 '질문 1' 텍스트 입력 수신"]
    LowTrack --> LowDraft["시장 요약 기반<br>일반 브리핑 초안 즉시 자동 완성"]
    LowDraft --> EmailLow["📧 최종 브리핑 이메일 자동 발송<br>(경영진 및 담당자 수신)"]
```

#### 1) 실행 환경 설정
- **Agents** 메뉴 ➔ **새 에이전트(New Agent)** 클릭
- 초기 **대화창 모드(Prompt 모드)**에서 시작합니다. (수동으로 노드를 일일이 배치하지 않고, 정교한 자연어 프롬프트 지시를 통해 에이전트 디자이너가 파이프라인 전체를 자동으로 구성하도록 합니다.)

#### 2) 워크플로우 에이전트 생성 프롬프트 입력
대화창의 입력 옴니바에 아래의 구조화된 프롬프트를 복사하여 입력하고 전송합니다:

> 💬 **워크플로우 에이전트 생성 프롬프트:**
> ```text
> 매일 오전 9시에 자동 실행되는 'AI 시장 뉴스 분석 및 경영진 브리핑 워크플로우 에이전트'를 만들어줘.
> 이 워크플로는 최신 AI 시장 뉴스를 분석해 경영진 브리핑을 작성하며, 총 3단계로 진행돼:
> 
> 1. 데이터 수집 및 분석:
> - Google 검색 도구를 활용해 지난 24시간 동안의 'AI 규제' 및 '기업 AI 도입' 뉴스를 실시간으로 수집해.
> - 수집된 정보를 바탕으로 시장 요약, 주요 핵심 주제, 그리고 기업에 미치는 위협 수준('High' 또는 'Low')을 자동 도출해.
> 
> 2. 조건 분기:
> - 분석된 위협 수준에 따라 작업을 'High(고위협)' 트랙과 'Else(일반)' 트랙 두 가지 경로로 자동 전환해.
> 
> 3. 트랙별 실행, 승인 및 이메일 발송:
> • High 트랙:
>   - 담당자에게 장문의 '홍보 대응 전략 지침' 입력을 요청해.
>   - 담당자가 입력한 지침과 시장 요약을 통합하여 완성도 높은 전문 브리핑 초안을 작성해.
>   - 리스크 관리를 위해 사람의 필수 승인(Review/Approval) 절차를 거치도록 해.
>   - 승인이 완료되면 최종 브리핑 결과를 담당자 및 경영진 이메일로 자동 발송해.
> • Else 트랙:
>   - 사용자에게 간단한 '질문 1' 텍스트 입력을 받아.
>   - 별도의 승인 절차 없이 시장 요약만으로 일반 브리핑 초안을 즉시 자동 완성해.
>   - 완성된 최종 일반 브리핑 결과를 담당자 이메일로 즉시 자동 발송해.
> 
> 전체적인 최종 처리 결과는 사용자가 메일로 바로 확인할 수 있도록 모두 이메일(Email/Gmail 전송 액션)로 전달해줘.
> 에이전트 구성 및 모든 안내 문구, 질문 폼, 브리핑 양식, 이메일 본문 언어는 완벽한 한국어로 작성해줘.
> ```

#### 3) 자동 생성된 Flow 뷰 구조 검토 및 확인
1. AI가 파이프라인 생성을 완료하면 상단의 **Flow 뷰** 탭을 클릭하여 시각적 흐름도가 의도대로 구축되었는지 확인합니다:
   - **스케줄 트리거 (Schedule Trigger)**: 매일 오전 09:00 (Daily at 09:00 AM) 자동 실행 주기 바인딩 확인
   - **검색 노드 (Google Search)**: 'AI 규제' 및 '기업 AI 도입' 수집 쿼리 연동
   - **조건 분기 노드 (Branching Node)**: 위협 수준 평가에 따른 `High` vs `Else` 분기 경로 형성
   - **인간 입력 노드 (Human Input)**: High 트랙(`홍보 대응 전략 지침`) 및 Else 트랙(`질문 1`) 입력 필드
   - **승인 게이트 노드 (Review & Approval)**: High 트랙에 배치된 사람의 필수 검토 게이트
   - **이메일 액션 노드 (Send Email / Gmail)**: 각 트랙의 최종 결과를 수신자 메일함으로 전송하는 발송 액션
2. 우측 상단의 **생성(Create)** 또는 **업데이트(Update)**를 클릭하여 워크플로우를 저장합니다.

#### 4) 테스트 실행 및 트랙별 이메일 수신 검증
1. 우측 테스트 대화창에서 워크플로우를 즉시 트리거합니다:
   > 💬 **테스트 실행 프롬프트:**
   > ```text

### Lab 5. 채용 전형 총괄 오케스트레이터 및 서브 에이전트 설계

채용 서류 검토 업무를 위해, 단일 에이전트의 토큰 및 추론 한계를 극복하는 **루트 오케스트레이터(Root Agent) 1개 + 전문 하위 에이전트(Sub-Agents) 3개**로 구성된 계층형 멀티 에이전트 아키텍처를 설계합니다.

```mermaid
graph TD
    A[사용자: 지원서 PDF 첨부] --> B[Root: GOOG전자 채용 총괄 에이전트]
    B -->|Step 1: 심층 서류 평가 의뢰| C[Sub 1: 서류 심층 평가자]
    C -->|점수 100점 & 인재상 & 리스크 반환| B
    B -->|Step 2: 고유명사 팩트체크 의뢰| D[Sub 2: 백그라운드 팩트체커]
    D -->|검증 결과 & Google Search URL 반환| B
    B -->|Step 3: 심층 면접 질문 의뢰<br>+ Step 1 평가 및 Step 2 팩트체크 맥락 전달| E[Sub 3: 면접 질문 기획자]
    E -->|기술적 압박 꼬리 질문 3가지 반환| B
    B --> F[단 하나의 최종 종합 검토 리포트 출력]
```

#### 1) 메인 루트 에이전트 구성: GOOG전자 채용 총괄 에이전트
- **Name:** `GOOG전자 채용 총괄 에이전트`
- **Description:** `채용 프로세스 전체를 총괄하며, 하위 전문가 에이전트(Sub-Agents)들을 지정된 순서대로 호출·실행하고 그 결과를 취합하여 최종 종합 리포트를 작성합니다.`

- **Knowledge (지식):** `2026년 GOOG전자 서류전형 평가 가이드라인.pdf` (`ge_lab/nocode_agent/resources/files/` 제공, Google Drive 바인딩)

- **원시 텍스트 Instruction:**

```text

당신은 GOOG전자의 채용 프로세스 전체를 오케스트레이션(통제 및 조율)하는 메인 에이전트입니다. 당신의 유일한 역할은 3명의 하위 전문가 에이전트를 정해진 순서대로 호출하고, 그들이 반환한 결과를 누락 없이 매끄럽게 취합하여 하나의 최종 종합 리포트를 작성하는 것입니다. 스스로 지원서를 직접 분석하거나 평가하지 말고, 반드시 하위 에이전트의 결과물만을 활용하십시오.

1. **Silent Execution:** 사용자에게 현재 어떤 단계를 진행 중인지, 계획이 무엇인지 설명하는 중간 프로세스를 절대 노출하지 마십시오. 오직 최종 결과만 출력해야 합니다.

## Output Expectations
모든 하위 에이전트의 작업이 완료되면, 전달받은 결과들을 종합하여 아래 구조를 모두 포함한 **단 하나의 최종 리포트**만 사용자에게 출력하십시오. 중간 과정이나 에이전트 간의 대화 흔적은 모두 숨겨야 합니다.
```

### Lab 6. 컨텍스트 인수인계(Hand-off) 및 침묵 실행(Silent Execution) 파이프라인 검증

1. 제작된 `GOOG전자 채용 총괄 에이전트`와의 대화창을 엽니다.
2. 입력창의 `+` 아이콘을 누르고 공유 드라이브에서 `GOOG전자 입사지원서_이OO.pdf` 파일을 첨부합니다.
3. 전송 버튼을 누르고 멀티 에이전트 파이프라인의 오케스트레이션 과정을 관찰합니다.

#### 2) 실행 결과 확인
- 에이전트가 백그라운드에서 Step 1, Step 2, Step 3를 차례대로 호출합니다.
- 대화창에는 하위 에이전트들의 잡다한 중간 대화가 노출되지 않으며, 모든 처리가 완료된 후 하나의 완성형 마크다운 종합 리포트가 화면에 출력됩니다.
- 새로운 대화 세션에서 `GOOG전자 입사지원서_김OO.pdf`를 첨부하여 다른 지원자에 대한 평가도 동일한 파이프라인으로 정확히 재현되는지 교차 검증합니다.

#### 3) 검증 포인트
- [ ] 중간 과정의 하위 에이전트 메시지나 불필요한 생각(Thinking) 노출 없이 최종 리포트만 깔끔하게 표시되는가 (Silent Execution)?
- [ ] Sub-Agent 2의 팩트체크 결과에 실제 유효한 Google Search 출처 URL이 포함되어 있는가?
- [ ] Sub-Agent 3의 면접 질문이 Sub-Agent 1(평가 리스크)과 Sub-Agent 2(팩트체크)의 내용을 정확히 인계받아 유기적으로 작성되었는가 (Context Forwarding)?
- [ ] 총점에 따른 PASS/FAIL/HOLD 추천 판정이 사내 가이드라인 기준에 부합하는가?

## 6. No-Code & Multi-Agent 프롬프트 엔지니어링 원칙 (Authoring Guide)

성공적인 No-Code 및 Multi-Agent 랩을 제작하기 위해 반드시 준수해야 하는 **5대 프롬프트 설계 원칙(Golden Rules)**입니다.

### 1️⃣ 침묵 실행 원칙 (Silent Execution Protocol)
- 오케스트레이터(Root Agent)가 하위 에이전트를 호출할 때 사용자가 중간 과정("Step 1을 시작합니다", "팩트체크 중입니다")을 볼 수 없도록 **`Silent Execution` 지침을 강제**해야 합니다.
- 사용자는 복잡한 에이전트 간 내부 핑퐁 대화가 아닌, 오직 **최종 완성형 단일 리포트**만 받아보아야 최고의 사용자 경험을 얻을 수 있습니다.

### 2️⃣ 명시적 맥락 인수인계 (Explicit Hand-off & Context Injection)
- 하위 에이전트 간에는 직접 통신이 불가능하며, 반드시 상위 에이전트를 거쳐야 합니다.
- 따라서 상위 에이전트의 지침에 **"Step 1과 Step 2의 결과물 전체를 Step 3 에이전트 호출 시 컨텍스트 입력값으로 반드시 함께 전달하라"**는 명시적 지침을 포함해야 유기적인 후속 분석(꼬리 질문 기획 등)이 가능해집니다.

### 3️⃣ 엄격한 무환각 앵커링 (Strict Zero-Hallucination on Knowledge)
- 사내 지식 베이스(사규, 평가 기준표, 매뉴얼)를 기반으로 평가하거나 정보를 추출하는 하위 에이전트에는 반드시 **`Strict Zero-Hallucination: 문서에 명시되지 않은 사실을 자의적으로 유추하거나 지어내지 말 것`**을 선언해야 합니다.

### 4️⃣ 하위 에이전트 반환 전용 규칙 (Hand-off Return Only Rule)
- 모든 Sub-Agent에는 **`작업이 완료되면 분석 결과를 상위 에이전트(Parent Agent)에게만 직접 반환하고, 사용자에게 인사말을 건네거나 대화를 임의로 종료하지 말 것`**을 명시하여 세션 제어권이 이탈하는 현상을 원천 방지합니다.

### 5️⃣ 정형화된 출력 템플릿 강제 (Rigid Response Schema)
- 에이전트가 자유롭게 문장을 늘어놓지 않도록, 시스템 프롬프트 맨 하단에 `# Response Format` 섹션을 두고 마크다운 테이블, 불릿 포인트, 필수 기재 필드를 견본 형태로 고정하십시오.

## 7. 트러블슈팅 및 운영 권장사항 (FAQ)

### 7.1 현장 트러블슈팅 매트릭스

| 증상 및 오류 현상 | 발생 원인 | 권장 조치 및 해결 방법 |
| :--- | :--- | :--- |
| **하위 에이전트의 중간 답변이 화면에 노출됨** | Silent Execution 및 Hand-off 규칙 누락 | Root Agent 및 Sub-Agent 지침에 `"사용자에게 중간 프로세스를 일체 노출하지 말고 Parent Agent에게만 직접 반환하라"`는 문구를 볼드체로 보강 |
| **면접 질문이 서류 평가 내용과 동떨어짐** | Step 3 호출 시 컨텍스트 인수인계 누락 | Root Agent 지침의 Step 3 부분에 `"Step 1 평가 결과와 Step 2 팩트체크 리포트 전체를 Context로 전달하라"`는 문장 재확인 |
| **스케줄러가 설정 시간에 실행되지 않음** | 스케줄 활성화(Active) 누락 및 권한 만료 | 1. Schedule 탭에서 상태가 **Active**인지 확인<br>2. 에이전트에 바인딩된 OAuth 커넥터(Drive, Search, Gmail)의 인증 세션이 만료되지 않았는지 재승인 |
| **지식 문서(Knowledge)를 무시하고 일반 상식 답변** | RAG 바인딩 오류 또는 지침 우선순위 미지정 | 에이전트 노드에 지식 문서가 정상 첨부되었는지 확인하고, 프롬프트 서두에 `"첨부된 지식 문서를 절대적인 1차 기준으로 삼아라"`고 명시 |

### 7.2 자주 묻는 질문 (FAQ)

#### Q1. No-Code 에이전트 하나에 하위 서브 에이전트를 몇 개까지 연결할 수 있나요?
> **A:** 실무적으로는 단일 오케스트레이터당 **3개~5개 내외의 서브 에이전트**를 구성하는 것이 가장 이상적입니다. 서브 에이전트가 지나치게 많아지면 실행 지연(Latency)이 증가하고 컨텍스트 전달 과정에서 정보 압축 손실이 발생할 수 있으므로, 역할별로 명확히 분리된 정예 에이전트 구성을 권장합니다.

#### Q2. 사내 비공개 문서를 에이전트 Knowledge로 등록해도 보안상 안전한가요?
> **A:** 완벽히 안전합니다. 바인딩된 사내 문서는 Gemini Enterprise의 테넌트 보안 경계 내에서만 임베딩 및 검색되며, 모델 학습에 일체 활용되지 않습니다. 또한 에이전트를 조직에 공유하더라도 문서를 열람할 수 있는 권한은 Google Workspace의 접근 제어(ACL) 정책을 그대로 계승합니다.

#### Q3. Workflow Agent가 긴 백그라운드 작업을 수행할 때 브라우저를 계속 켜두어야 하나요?
> **A:** 아닙니다. 장시간 소요되는 워크플로우나 스케줄링된 에이전트는 서버리스 인프라에서 독립적으로 실행되며, 처리가 완료되면 **스마트 수신함(Inbox)** 및 등록된 **이메일(Gmail)**로 결과 리포트가 자동 발송되므로 브라우저를 닫아두어도 안전합니다.
